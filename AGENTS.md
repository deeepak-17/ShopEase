# ShopEase: context for AI coding agents

Read this before any task. It applies to every agent in this repo
(Antigravity or any other).

## What we're building

A Tanglish voice ledger for small shops in Tamil Nadu. The shopkeeper speaks
("Ravi anna ku 250 kadan"), Gnani Prisma transcribes, our parser turns the
words into ledger actions, and Gnani Timbre replies in Tamil. Python 3.12+,
FastAPI, SQLite, a phone-first web UI. Spec: `docs/spec.pdf` (old name: KadaiMate).

Deadline: demo post live Nov 7, 2026; submission Nov 9. Feature freeze Nov 6.
Scope is the spec's Must list first. Do not add features beyond the issue
you're working on.

- Shared files change only in a dedicated small PR that the other member reviews.
  If a task seems to need a change to `contracts.py`, stop and tell the human.

## The contract (where A and B meet)

`src/shopease/contracts.py`: A's parser returns a `ParseResult` (a tuple of
`Intent`s). B's `Ledger.apply(result)` returns a `Reply`. Build against the
contract, never against the other member's internals:
- B tests with hand-built `ParseResult` objects, not by calling the parser.
- A tests against a fake `Ledger`, not B's SQLite code.

## Facts from real Prisma tests (Nov 2)

- Prisma returns **no confidence score**. Confirmation must use other signals:
  unknown name, unusual amount for that customer, `ParseResult.is_ambiguous`.
- Names come back in **Tamil or Latin script** (`Ravi அண்ணாவுக்கு`, `ரவிக்கு`).
  Name matching must handle both.
- Amounts are `Decimal` rupees, already converted from Tamil number words by the parser.
- Timbre voice comes from the `TIMBRE_VOICE` env var (currently `Asmita`). Never hard-code it.

## How to work

- Test first: write a failing pytest test, make it pass, then refactor. Run `pytest`.
- Small, immutable data (`@dataclass(frozen=True)`), type hints on every
  function, functions under 50 lines, `logging` not `print`.
- Secrets only in `.env` (git-ignored). Never commit `.env`, API keys or voice
  recordings (`clips/`).
- One branch per issue: `b/<short-name>` for Member B, `a/<short-name>` for A.
  Never commit to `main`. Open a PR with `Closes #<issue>`.
- Commit messages: `feat: ...`, `fix: ...`, `test: ...`, `docs: ...`, `chore: ...`.
- No AI attribution anywhere: no co-author trailers, no "generated by" footers
  in commits, PRs or docs.
